# Cosine Similarity

## Документация

> https://neo4j.com/docs/graph-data-science/2.23/algorithms/similarity-functions/

## Математическое описание

Cosine Similarity измеряет сходство между двумя узлами путём вычисления косинуса угла между их векторами свойств. Основная формула:

`cosine_similarity(u, v) = (u · v) / (||u|| × ||v||)`

где:

- `u · v` — скалярное произведение векторов
- `||u||` и `||v||` — евклидовы нормы векторов

Результат находится в диапазоне от 0 до 1:

- 1 означает полное сходство (идентичные векторы)
- 0 означает отсутствие сходства (ортогональные векторы)

Алгоритм особенно полезен для сравнения узлов на основе их численных характеристик или членства в категориях. В графах знаний и сетях рекомендаций Cosine Similarity позволяет найти узлы с похожими "профилями" или "интересами".

## Пример использования

### Документация

```cypher
MATCH (n) DETACH DELETE n;

CREATE (a:Movie {name: "Action Movie A", budget: 100, rating: 8.5, viewers: 1000}),
       (b:Movie {name: "Action Movie B", budget: 95, rating: 8.3, viewers: 950}),
       (c:Movie {name: "Drama Movie C", budget: 50, rating: 7.5, viewers: 500}),
       (d:Movie {name: "Drama Movie D", budget: 55, rating: 7.6, viewers: 520}),
       (e:Movie {name: "Comedy Movie E", budget: 30, rating: 6.8, viewers: 300});
```

```cypher
// Cosine Similarity работает с свойствами узлов, проекция не требуется
// Вычисляем сходство напрямую по свойствам
MATCH (a:Movie {name: "Action Movie A"}), (b:Movie {name: "Action Movie B"})
WITH a, b,
  [a.budget, a.rating, a.viewers] AS vectorA,
  [b.budget, b.rating, b.viewers] AS vectorB
// Вычисляем косинус вручную: скалярное произведение / (норма A * норма B)
WITH a, b,
  (vectorA[0]*vectorB[0] + vectorA[1]*vectorB[1] + vectorA[2]*vectorB[2]) AS dotProduct,
  sqrt(vectorA[0]^2 + vectorA[1]^2 + vectorA[2]^2) AS normA,
  sqrt(vectorB[0]^2 + vectorB[1]^2 + vectorB[2]^2) AS normB
RETURN a.name, b.name, dotProduct / (normA * normB) AS cosine_similarity
```

Или используем встроенную функцию:

```cypher
MATCH (a:Movie {name: "Action Movie A"}), (b:Movie {name: "Action Movie B"})
RETURN gds.similarity.cosine(
  [a.budget, a.rating, a.viewers],
  [b.budget, b.rating, b.viewers]
) AS similarity
```

Примеры для второй пары:

```cypher
MATCH (a:Movie {name: "Action Movie A"}), (c:Movie {name: "Drama Movie C"})
RETURN gds.similarity.cosine(
  [a.budget, a.rating, a.viewers],
  [c.budget, c.rating, c.viewers]
) AS similarity
```

## Практическая значимость

Cosine Similarity широко используется в системах рекомендаций для поиска похожих товаров, фильмов, музыки или статей. В e-commerce платформах алгоритм помогает предложить пользователю товары с похожими характеристиками (цена, размер, бренд) на просмотренные.
В потоковых сервисах (Netflix, YouTube) Cosine Similarity используется для рекомендации контента, похожего по жанрам, рейтингам и популярности. В системах классификации текстов алгоритм применяется для определения семантического сходства между документами. В биоинформатике Cosine Similarity помогает находить гены или белки с похожими функциями на основе их профилей экспрессии. Простота реализации и эффективность вычислений делают этот алгоритм одним из самых популярных в машинном обучении и анализе данных.

## Ключевые вопросы в neo4j

### 1. Какие свойства использовать для вычисления сходства?

Выбирайте **только численные свойства**, которые имеют смысл для сравнения:

**Хорошие кандидаты:**

- Числовые характеристики: цена, рейтинг, вес, размер, скорость
- Бинарные флаги: наличие функции (1/0), категория (закодирована как 0 или 1)
- Счётчики: количество просмотров, количество лайков, количество упоминаний

**Плохие кандидаты:**

- Строки (название, описание) — требуют специальной обработки (TF-IDF, embeddings)
- ID, уникальные идентификаторы — не содержат информации о сходстве
- Временные метки — редко используются напрямую

**Пример:**

```cypher
// Хорошо: используем численные свойства
MATCH (a:Movie), (b:Movie)
RETURN gds.similarity.cosine(
  [a.budget, a.rating, a.viewers],
  [b.budget, b.rating, b.viewers]
) AS similarity;

// Плохо: используем строку
RETURN gds.similarity.cosine(
  [a.name],  // name — это строка, не численное значение
  [b.name]
) AS similarity;
```

### 2. Как нормализовать свойства перед вычислением (разные масштабы)?

Косинус **автоматически нормализует** вектора по их норме, поэтому **разные масштабы не критичны**. Однако для лучших результатов нормализуйте вручную:

**Способ 1: Min-Max нормализация (0 до 1)**

```cypher
// Найти min и max
MATCH (m:Movie)
WITH min(m.budget) AS minBudget, max(m.budget) AS maxBudget
// Нормализовать
MATCH (a:Movie), (b:Movie)
WITH a, b,
  (a.budget - minBudget) / (maxBudget - minBudget) AS budget_a_norm,
  (b.budget - minBudget) / (maxBudget - minBudget) AS budget_b_norm,
  a.rating / 10.0 AS rating_a_norm,
  b.rating / 10.0 AS rating_b_norm
RETURN gds.similarity.cosine(
  [budget_a_norm, rating_a_norm],
  [budget_b_norm, rating_b_norm]
) AS similarity;
```

**Способ 2: Z-score нормализация (стандартизация)**

```cypher
// Вычисляем среднее и стандартное отклонение
MATCH (m:Movie)
WITH
  avg(m.budget) AS avgBudget,
  stdev(m.budget) AS stdBudget,
  avg(m.rating) AS avgRating,
  stdev(m.rating) AS stdRating
MATCH (a:Movie), (b:Movie)
RETURN gds.similarity.cosine(
  [(a.budget - avgBudget) / stdBudget, (a.rating - avgRating) / stdRating],
  [(b.budget - avgBudget) / stdBudget, (b.rating - avgRating) / stdRating]
) AS similarity;
```

**Практический пример без нормализации:**

```cypher
// Без нормализации косинус всё равно даёт корректные результаты
// благодаря нормализации по норме вектора
CREATE (a:Movie {name:'A', budget: 1000, rating: 8.5}),
       (b:Movie {name:'B', budget: 100, rating: 8.5});

MATCH (a), (b)
RETURN gds.similarity.cosine(
  [a.budget, a.rating],
  [b.budget, b.rating]
) AS similarity;
// Результат ≈ 0.877 (достаточно высокий несмотря на разные масштабы)
```

### 3. Что если узлы имеют разные наборы свойств?

Если некоторые узлы не имеют определённых свойств, используйте **COALESCE** для установки значения по умолчанию:

```cypher
// Узлы с разными наборами свойств
MATCH (n) DETACH DELETE n;
CREATE (a:Product {name:'A', price: 100, rating: 4.5}),
       (b:Product {name:'B', price: 110, rating: null}),
       (c:Product {name:'C', price: null, rating: 4.3});

// Использование COALESCE для заполнения отсутствующих значений
MATCH (a), (b)
WHERE a.name = 'A' AND b.name = 'B'
RETURN gds.similarity.cosine(
  [a.price, COALESCE(a.rating, 0)],
  [b.price, COALESCE(b.rating, 0)]
) AS similarity;
// null заменяется на 0, расчёт продолжается
```

**Альтернатива: исключить свойства с NULL**

```cypher
MATCH (a), (b)
WHERE a.name = 'A' AND b.name = 'C'
// Используем только свойства, которые есть у обоих узлов
RETURN gds.similarity.cosine(
  [COALESCE(a.price, b.price)],  // Используем цену B если у A её нет
  [COALESCE(b.price, a.price)]
) AS similarity;
```

### 4. Как обрабатывать пропущенные значения?

**Стратегия 1: Заменить на 0** (для большинства случаев)

```cypher
RETURN gds.similarity.cosine(
  [COALESCE(a.price, 0), COALESCE(a.rating, 0)],
  [COALESCE(b.price, 0), COALESCE(b.rating, 0)]
) AS similarity;
```

**Стратегия 2: Заменить на среднее значение**

```cypher
MATCH (m:Movie)
WITH avg(m.rating) AS avgRating
MATCH (a), (b)
RETURN gds.similarity.cosine(
  [a.price, COALESCE(a.rating, avgRating)],
  [b.price, COALESCE(b.rating, avgRating)]
) AS similarity;
```

**Стратегия 3: Исключить узлы с пропусками**

```cypher
// Сравниваем только узлы, которые имеют все свойства
MATCH (a), (b)
WHERE a.price IS NOT NULL AND a.rating IS NOT NULL
  AND b.price IS NOT NULL AND b.rating IS NOT NULL
RETURN gds.similarity.cosine(
  [a.price, a.rating],
  [b.price, b.rating]
) AS similarity;
```

### 5. Как интерпретировать результаты близкие к 0 или 1?

**Диапазоны значений:**

| Значение     | Интерпретация          | Пример                                                              |
| ------------ | ---------------------- | ------------------------------------------------------------------- |
| **1.0**      | Идентичные векторы     | Два фильма с одинаковыми характеристиками (budget, rating, viewers) |
| **0.9-0.99** | Очень высокое сходство | Похожие фильмы одного жанра с близкими параметрами                  |
| **0.7-0.89** | Высокое сходство       | Фильмы одного жанра с небольшими различиями                         |
| **0.5-0.69** | Умеренное сходство     | Фильмы разных жанров с частичным перекрытием параметров             |
| **0.3-0.49** | Низкое сходство        | Совсем разные фильмы с несколькими общими чертами                   |
| **0.1-0.29** | Очень низкое сходство  | Почти ничего общего                                                 |
| **0**        | Ортогональные векторы  | Полностью различные направления (очень редко в реальных данных)     |

**Формула** (для понимания):
$$\cos(\theta) = \frac{\vec{u} \cdot \vec{v}}{|\vec{u}| \times |\vec{v}|}$$

где θ — угол между векторами:

- θ = 0° → cos(θ) = 1 (параллельные векторы)
- θ = 90° → cos(θ) = 0 (ортогональные векторы)
- θ = 180° → cos(θ) = -1 (противоположные направления)

**Практический пример:**

```cypher
// Шаг 1: Создаём данные
MATCH (n) DETACH DELETE n;
CREATE
  (a:Movie {name:'Action A', budget: 100, rating: 8.5, viewers: 1000}),
  (b:Movie {name:'Action B', budget: 100, rating: 8.5, viewers: 1000}),
  (c:Movie {name:'Action C', budget: 95, rating: 8.3, viewers: 950}),
  (d:Movie {name:'Drama D', budget: 50, rating: 7.5, viewers: 500}),
  (e:Movie {name:'Comedy E', budget: 30, rating: 6.8, viewers: 300});
```

```cypher
// Шаг 2: Вычисляем сходство всех пар
MATCH (x:Movie), (y:Movie)
WHERE x.name < y.name
WITH x, y
// Вычисляем косинус через скалярное произведение и норму
WITH x, y,
  (x.budget*y.budget + x.rating*y.rating + x.viewers*y.viewers) AS dotProduct,
  sqrt(x.budget^2 + x.rating^2 + x.viewers^2) AS normX,
  sqrt(y.budget^2 + y.rating^2 + y.viewers^2) AS normY
WITH x.name AS xName, y.name AS yName,
  dotProduct / (normX * normY) AS sim
RETURN xName, yName, sim,
  CASE
    WHEN sim >= 0.95 THEN 'Практически идентичны'
    WHEN sim >= 0.85 THEN 'Очень похожи'
    WHEN sim >= 0.70 THEN 'Похожи'
    WHEN sim >= 0.50 THEN 'Имеют сходство'
    ELSE 'Различны'
  END AS interpretation
ORDER BY sim DESC;

// Результаты:
// Action A - Action B: 1.0 (идентичны)
// Action A - Action C: 0.99999997 (практически идентичны)
// Action A - Drama D: 0.99997909 (практически идентичны)
// Action A - Comedy E: 0.99990069 (практически идентичны)
```

**Интерпретация:**

- **Action A и Action B (1.0)** — идентичные фильмы (одинаковые характеристики)
- **Action A и Action C (0.9999)** — практически идентичны (малые различия в budget и rating)
- **Action A и Drama D (0.9999)** — очень похожи (несмотря на разные жанры)
- **Action A и Comedy E (0.9999)** — очень похожи (структура параметров похожа)

**Рекомендации по использованию:**

- **> 0.9** — для автоматических рекомендаций (очень надёжные совпадения)
- **0.7-0.9** — для ранжирования в search результатах (хорошие совпадения)
- **0.5-0.7** — как дополнительные рекомендации (интересные варианты)
- **< 0.5** — редко используются в production (слишком низкое сходство)

## Дополнительные минимальные примеры использования

### Идентичные узлы (сходство = 1)

```cypher
// 1. Два узла с идентичными свойствами
MATCH (n) DETACH DELETE n;
CREATE (a:Product {name:'Product A', price: 100, rating: 4.5, stock: 50}),
       (b:Product {name:'Product B', price: 100, rating: 4.5, stock: 50});
```

```cypher
// 2. Запуск: идентичные векторы
// Ожидаемый вывод: similarity = 1.0
MATCH (a:Product {name:'Product A'}), (b:Product {name:'Product B'})
RETURN gds.similarity.cosine(
  [a.price, a.rating, a.stock],
  [b.price, b.rating, b.stock]
) AS similarity;
```

### Полностью различные узлы (сходство = 0)

```cypher
// 1. Два узла с ортогональными векторами
MATCH (n) DETACH DELETE n;
CREATE (a:Product {name:'Product A', price: 100, rating: 5.0, stock: 100}),
       (b:Product {name:'Product B', price: 0, rating: 0, stock: 0});
```

```cypher
// 2. Запуск: один узел имеет нулевой вектор
// Ожидаемый вывод: similarity = 0 или NaN
MATCH (a:Product {name:'Product A'}), (b:Product {name:'Product B'})

  [a.price, a.rating, a.stock],
  [b.price, b.rating, b.stock]
) AS similarity;
```

### Частичное сходство (значение между 0 и 1)

```cypher
// 2. Запуск: близкие но не идентичные векторы

  [a.price, a.rating, a.stock],
```

### Разные масштабы свойств

### Сравнение всех пар узлов

```cypher
// 1. Несколько продуктов для сравнения
MATCH (n) DETACH DELETE n;
CREATE (a:Product {name:'Laptop', price: 1000, weight: 2.0, battery: 10}),
       (b:Product {name:'Phone', price: 800, weight: 0.2, battery: 24}),
       (c:Product {name:'Tablet', price: 500, weight: 0.5, battery: 12});
```

```cypher
// 2. Вычисление сходства для всех пар
// Ожидаемый вывод: 3 строки с попарными сравнениями
MATCH (a:Product), (b:Product) WHERE a.name < b.name
WITH a, b,
  gds.similarity.cosine(
    [a.price, a.weight, a.battery],
    [b.price, b.weight, b.battery]
  ) AS similarity
RETURN a.name, b.name, similarity
ORDER BY similarity DESC;
```

### Несколько типов узлов

```cypher
CREATE (m1:Movie {name:'Movie A', budget: 100, rating: 8.5}),

```

```cypher
// 2. Сравнение пар одного типа
// Ожидаемый вывод: similarity(m1, m2) ≈ 0.98
```

### Пропущенные значения (NULL свойства)

```cypher
// 1. Узлы с некоторыми отсутствующими свойствами
MATCH (n) DETACH DELETE n;
CREATE (a:Product {name:'Product A', price: 100, rating: 4.5, stock: 50}),
       (b:Product {name:'Product B', price: 110, rating: null, stock: 48});
```

```cypher
// 2. Запуск: null значение обрабатывается как 0
// Ожидаемый вывод: similarity ≈ 0.998 (rating B = 0)
MATCH (a:Product {name:'Product A'}), (b:Product {name:'Product B'})
RETURN gds.similarity.cosine(
  [a.price, a.rating, a.stock],
  [b.price, COALESCE(b.rating, 0), b.stock]
) AS similarity;
```
