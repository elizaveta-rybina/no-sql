# Adamic Adar

## Документация

> https://neo4j.com/docs/graph-data-science/2.23/algorithms/linkprediction/adamic-adar/

## Математическое описание

Алгоритм **Adamic Adar** - это метод предсказания связей в графах, который вычисляет сходство между двумя узлами на основе их общих соседей.
Основная идея заключается в том, что узлы с большим числом общих соседей более похожи и с большей вероятностью будут связаны в будущем.
Формула учитывает редкость общих соседей - соседей с низкой степенью (малое количество связей) считаются более информативными чем соседи с высокой степенью. Это позволяет отдать приоритет "специальным" общим соседям перед "универсальными" узлами, которые соединены почти со всеми в графе. Алгоритм широко применяется для предсказания новых дружеских связей в социальных сетях, рекомендации контактов и идентификации потенциальных совместных авторов в сетях цитирования.

## Пример использования

### Документация

```cypher
MATCH (n) DETACH DELETE n;

CREATE (a:Person {name: 'Alice'}),
       (b:Person {name: 'Bob'}),
       (c:Person {name: 'Charlie'}),
       (d:Person {name: 'Diana'}),
       (e:Person {name: 'Eve'}),
       (f:Person {name: 'Frank'}),
       (a)-[:KNOWS]->(b),
       (a)-[:KNOWS]->(c),
       (a)-[:KNOWS]->(d),
       (b)-[:KNOWS]->(c),
       (b)-[:KNOWS]->(e),
       (c)-[:KNOWS]->(d),
       (c)-[:KNOWS]->(e),
       (d)-[:KNOWS]->(f),
       (e)-[:KNOWS]->(f);
```

### Итого

Alice → Bob
Alice → Charlie
Alice → Diana
Bob → Charlie
Bob → Eve
Charlie → Diana
Charlie → Eve
Diana → Frank
Eve → Frank

```cypher
// удаляем проекцию графа
```

### Объяснение:

- Общие соседи:

Bob (связан и с Alice, и с Eve)
Charlie (связан и с Alice, и с Eve)

- Степени узлов:

Bob: 3 связи (Alice, Charlie, Eve)
Charlie: 4 связи (Alice, Bob, Diana, Eve)

- Вычисление:

score = 1/log(3) + 1/log(4)
= 1/1.0986 + 1/1.3863
= 0.9102 + 0.7213
≈ 1.63

## Практическая значимость

Алгоритм Adamic Adar широко применяется в социальных сетях для рекомендации новых друзей и контактов пользователям на основе их общих связей.
В профессиональных сетях (LinkedIn, ResearchGate) он помогает предложить потенциальных сотрудников, соавторов и партнеров. Алгоритм также используется в системах рекомендации контента, где узлы представляют пользователей или элементы, и предсказание связей помогает выявить скрытые интересы. В биологических сетях (сетях взаимодействия белков) алгоритм помогает предсказать новые взаимодействия белков. В онлайн-сообществах и форумах он может использоваться для выявления потенциальных сотрудничеств и командных моментов. Простота вычисления и интерпретируемость результатов делают Adamic Adar популярным инструментом для начального анализа и быстрого прототипирования систем предсказания связей.

## Ключевые вопросы в neo4j

### 1. Что если два узла уже соединены (не нужно предсказывать)?

Алгоритм **не проверяет наличие существующих связей** и всё равно вычислит score. Это нормально, так как алгоритм оценивает "силу" связи, а не только предсказывает новые.

**Решение:** Используйте фильтрацию в запросе:

```cypher
// Исключаем узлы, которые уже связаны
MATCH (source:Person {name:'Alice'}), (target:Person)
WHERE NOT (source)-[:KNOWS]-(target) AND source <> target
RETURN target.name, gds.alpha.linkprediction.adamicAdar(source, target) AS score
ORDER BY score DESC;
```

### 2. Что если у узлов нет общих соседей?

Алгоритм вернёт **score = 0**, что означает отсутствие сходства и низкую вероятность связи.

**Пример:**

```cypher
// Alice и Bob в разных компонентах графа
MATCH (n) DETACH DELETE n;
CREATE (a:Person {name:'Alice'}), (b:Person {name:'Bob'}),
       (c:Person {name:'Charlie'}), (d:Person {name:'Diana'}),
       (a)-[:KNOWS]->(c), (b)-[:KNOWS]->(d);

MATCH (source:Person {name:'Alice'}), (target:Person {name:'Bob'})
RETURN gds.alpha.linkprediction.adamicAdar(source, target) AS score;
// Результат: 0
```

### 3. Как работает алгоритм с направленными и ненаправленными рёбрами?

По умолчанию функция `gds.alpha.linkprediction.adamicAdar` **игнорирует направление** рёбер и рассматривает граф как ненаправленный.

**Направление важно при:**

- Использовании GDS процедур (не alpha функции)
- Явном указании ориентации в проекции графа

**Пример:**

```cypher
// Направление стрелок в CREATE не влияет на результат
CREATE (a)-[:KNOWS]->(c), (b)-[:KNOWS]->(c);
// Эквивалентно ненаправленным связям для Adamic Adar
```

### 4. Как исключить существующие связи из анализа?

Используйте **WHERE NOT EXISTS** или **NOT** для фильтрации:

```cypher
// Найти топ-5 рекомендаций для Alice (только несвязанные узлы)
MATCH (source:Person {name:'Alice'}), (target:Person)
WHERE source <> target
  AND NOT (source)-[:KNOWS]-(target)
WITH source, target, gds.alpha.linkprediction.adamicAdar(source, target) AS score
WHERE score > 0
RETURN target.name, score
ORDER BY score DESC
LIMIT 5;
```

**Альтернатива с подзапросом:**

```cypher
MATCH (source:Person {name:'Alice'}), (target:Person)
WHERE source <> target
  AND NOT EXISTS { MATCH (source)-[:KNOWS]-(target) }
RETURN target.name, gds.alpha.linkprediction.adamicAdar(source, target) AS score
ORDER BY score DESC;
```

### 5. Как интерпретировать значение similarity (выше = более вероятна связь)?

**Диапазоны значений:**

- **score = 0** — нет общих соседей, связь очень маловероятна
- **0 < score < 1** — слабое сходство (1-2 общих соседа с высокой степенью)
- **1 ≤ score < 2** — умеренное сходство (несколько общих соседей)
- **score ≥ 2** — сильное сходство (много общих соседей или соседи с низкой степенью)
- **score ≥ 3** — очень высокая вероятность связи

**Формула:**
$$\text{score} = \sum_{z \in \text{общие соседи}} \frac{1}{\log(\text{degree}(z))}$$

**Интерпретация:**

- Чем **меньше степень** у общего соседа, тем **больше** его вклад в score
- Общий друг с 2 связями даёт $\frac{1}{\log(2)} \approx 1.44$
- Общий друг с 10 связями даёт $\frac{1}{\log(10)} \approx 0.43$

**Практический пример:**

```cypher
// Ранжирование потенциальных связей
MATCH (source:Person {name:'Alice'}), (target:Person)
WHERE source <> target AND NOT (source)-[:KNOWS]-(target)
WITH target.name AS person,
     gds.alpha.linkprediction.adamicAdar(source, target) AS score
WHERE score > 0
RETURN person, score,
  CASE
    WHEN score >= 2 THEN 'Высокая вероятность'
    WHEN score >= 1 THEN 'Средняя вероятность'
    ELSE 'Низкая вероятность'
  END AS recommendation
ORDER BY score DESC;
```
